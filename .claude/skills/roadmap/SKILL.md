# 리뷰 플레이그라운드 로드맵

설계 원본은 프로젝트 루트의 `plan.md`다. 이 스킬은 plan.md 13장의 개발 순서를 단계별 작업, 완료 기준, 확인 항목으로 풀어 둔 것이다.

## 현재 상태

- 진행 파일(`progress.md`):

```!
cat progress.md 2>/dev/null || echo "(없음 — 처음 실행이다. 아래 '처음 실행' 절차를 따른다)"
```

- 최근 커밋: !`git log --oneline -5 2>/dev/null || echo "(git 기록 없음)"`
- 인자: `$ARGUMENTS`

## 참고 파일

- 단계별 상세 작업과 완료 기준: `${CLAUDE_SKILL_DIR}/phases.md` — 단계를 진행하기 전에 해당 단계 부분을 반드시 읽는다.
- 진행 파일 템플릿: `${CLAUDE_SKILL_DIR}/progress-template.md`

## 처음 실행

`progress.md`가 없으면:
1. `${CLAUDE_SKILL_DIR}/progress-template.md`를 프로젝트 루트의 `progress.md`로 복사한다.
2. 사용자에게 Knot 저장소의 로컬 경로를 물어 `progress.md`의 `Knot 경로`에 적는다. 코드는 처음부터 이 저장소(prplay)에서 작성하고, Knot은 빌드 대상으로 경로만 참조한다(plan.md 13장 '작업 위치').
3. 그다음 `status` 모드로 이어간다.

## 모드

인자에 따라 하나를 실행한다.

### `status` 또는 인자 없음
1. `progress.md`에서 단계별 완료 개수(`[x]` / 전체)를 표로 보여준다.
2. 미해결 확인 항목(plan.md 14장)과 막힌 점(`## 막힌 점`)을 보여준다.
3. 다음에 할 작업 하나를 추천하고, `/roadmap next`로 시작할 수 있다고 알려준다.

### `next`
1. 체크되지 않은 가장 앞 단계의 가장 앞 작업 하나를 고른다. 앞 단계의 완료 기준을 만족하지 못했으면 그 단계를 먼저 마무리한다.
2. `phases.md`에서 그 작업의 설명과 참조한 plan.md 절을 읽고, plan.md의 해당 절도 읽는다.
3. 무엇을 할지 두세 줄로 말한 뒤 바로 구현한다.
4. 끝나면 아래 '작업을 마칠 때' 절차를 따른다.

### `<단계번호>` (1-8)
해당 단계의 목표, 작업 목록과 진행 상태, 완료 기준을 보여주고, 그 단계에서 체크되지 않은 첫 작업부터 `next`와 같은 방식으로 진행한다.

### `check <단계번호>`
해당 단계의 완료 기준을 하나씩 실제로 확인한다(빌드 실행, 파일 존재, `file://`로 열어 보기 등). 결과를 통과/실패로 보여주고, 모두 통과하면 `progress.md`에 단계 완료 날짜를 적는다. 확인할 수 없는 항목(아티팩트 업로드처럼 사람이 해야 하는 일)은 사용자에게 결과를 묻는다.

### `log <메모>`
`progress.md`의 `## 작업 기록`에 오늘 날짜와 메모를 한 줄 추가한다.

## 작업을 마칠 때

1. `progress.md`에서 끝난 작업을 `[x]`로 바꾼다.
2. `## 작업 기록`에 `- YYYY-MM-DD <단계>.<작업번호> <한 줄 요약>`을 추가한다.
3. 작업 중에 plan.md 14장의 확인 항목에 대한 답을 얻었으면:
   - `progress.md`의 확인 항목을 `[x]`로 바꾸고 결과를 한 줄 붙인다.
   - plan.md 14장 체크박스와, 결과가 설계를 바꾸는 경우 관련 절(예: 1장 표, 7장 공유 방식)도 고친다.
4. 막힌 점이 생기면 `## 막힌 점`에 적고 사용자에게 알린다.
5. 커밋은 사용자가 요청할 때만 한다.

## 규칙

- 한 번에 작업 하나만 한다. 다음 작업으로 넘어가기 전에 사용자에게 결과를 보여준다.
- plan.md에 적힌 결정(단일 HTML, Service Worker 없음, MemoryRouter, localStorage 키 형식 등)을 따른다. 바꿔야 할 이유가 생기면 구현 전에 사용자에게 먼저 말한다.
- Knot 저장소에는 파일을 만들거나 고치지 않는다(의존성 추가 포함). Knot에 맞춘 설정과 케이스는 prplay의 `targets/knot/`에 둔다. 예외는 plan.md 11.4의 PR #366 worktree 링크 테스트(사용자 승인)뿐이다.
- 라이브러리 버전별 옵션 이름(vite-plugin-svgr의 `include`, `exportType` 등)은 추측하지 말고 설치된 버전의 문서나 타입 정의로 확인한다.
- 모든 빌드 결과는 아티팩트에 올리기 전에 `file://`로 먼저 열어 확인한다.
