# 글쓰기 규칙

이 스킬이 쓰는 모든 글에 적용한다.

- `pr.ts`의 모든 문자열(`summary`, `background`, `intuition`, `diagrams`의 `caption`과 SVG 글자, `changes`, `codeWalk`의 `title`·`explain`, `decisions`, `reviewPoints`)
- 케이스 파일의 `title`, 프리셋·시나리오 이름, 주석
- AskUserQuestion의 question, label, description
- '끝나면'에서 사용자에게 보내는 보고

코드 식별자, 파일 경로, PR 제목(`title`)은 원래 모양대로 둔다.

## 기본

- 모든 문장은 완결된 문장으로 쓰고, 뜻이 분명하고 아주 쉽게 쓴다.
- 설명은 한국어로 쓰고, 독자는 JavaScript/TypeScript 개발자로 본다.
- 보고와 질문은 존댓말로 쓴다. `pr.ts`와 케이스 파일은 `example-pr.ts`처럼 "~한다" 체로 쓰되, `reviewPoints`처럼 리뷰어에게 부탁하는 문장은 존댓말로 쓴다.

## 피할 쓰기 방식

### 문장을 의미 없이 짧게 끊지 않기

앞 문장과 뒤 문장이 한 맥락이면 이어서 한 문장으로 쓴다.

```
차이는 클래스가 자동으로 해주는 부분입니다. new 강제(IsClassConstructor), # private 공식 지원 등입니다. // ❌
차이는 클래스가 자동으로 해주는 new 강제(IsClassConstructor), # private 공식 지원 등이 있습니다. // ✅

클래스 기반에서 이미 만들어진 인스턴스는 이렇게 부모를 바꿔도 영향받지 않습니다. 복사본이기 때문입니다. // ❌
클래스 기반에서 이미 만들어진 인스턴스는 복사본이기 때문에 이렇게 부모를 바꿔도 영향받지 않습니다. // ✅

밖에서는 잘 돌던 모델이라 이번에도 당연히 될 줄 알았다. 그런데 안 돌아갔다. // ❌
밖에서는 잘 돌던 모델이라 이번에도 당연히 될 줄 알았는데, 안 돌아갔다. // ✅
```

### 요약 선언문 뒤에 같은 내용의 묘사를 반복하지 않기

뒤따르는 묘사가 보여 줄 내용을 "~한 환경이었다" 같은 요약 문장으로 먼저 선언하지 않는다. 묘사가 먼저 말하게 하고, 요약이 필요하면 묘사 뒤에 한 번만 둔다. 같은 대상을 "~이었다/~였다" 규정문으로 두 문장 연속 쓰지 않는다.

```
치열하게 공부하고, 만나서 발표하고 토론하는 활동이었다. 각자가 몰입할 수 있는 환경이었다. 다들 자기 자리에서 몰두해 공부하고, 막히면 질문하고, 함께 풀어나갔다. // ❌
치열하게 공부하고, 만나서 발표하고 토론하는 활동이었다. 다들 자기 자리에서 몰두해 공부하다가, 막히면 질문하고 함께 풀어나갔다. // ✅
```

### 내용이 아닌 문장을 강조하지 않기

아래처럼 다음 내용을 예고만 하는 문장은 쓰지 않는다.

```
공부한 가장 중요한 축은 다음 문장이다.
프로토타입 관점에서 가장 직접적인 연결 지점입니다.
질문은 두 개로 모였다.
```

### 의미 없는 말 쓰지 않기

"이름이 비슷해 혼동하기 쉽습니다. 둘은 방향이 다릅니다."처럼 독자가 판단할 말을 넣지 않고, 설명만 쓴다.

### 뜻이 맞지 않는 단어 쓰지 않기

- "발표를 가른다": 발표는 가를 수 없다.
- "손에 잡히는 기준": 기준은 손에 잡히지 않는다.
- "백엔드와 객체지향을 처음 제대로 만나다": 사람이 아닌 것은 만날 수 없다.

### 너무 딱딱하게 쓰지 않기

```
"프로토타입 기반"은 이런 뜻입니다. // ❌
"프로토타입 기반"은 이렇다고 말할 수 있다. // ✅
```
